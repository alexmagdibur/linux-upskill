# Что исключено из курса и почему

Эти уроки нельзя выполнить без настоящей виртуальной машины со своим ядром (KVM) или без доступа к блочным устройствам и ядерным подсистемам. Из контейнера (даже системного, LXD) их воспроизвести нельзя, а имитация вводила бы ученика в заблуждение, поэтому они **исключены из курса**, а нумерация уроков пересчитана без дыр. Идентификаторы оставшихся заданий (`ld-NNN`) сохранены, чтобы не терять прогресс.


## Загрузка и ядро

- `ld-041` — Постройте цепочку firmware → bootloader → kernel → initramfs → PID 1 на своей VM
- `ld-042` — Измените неопасный параметр kernel command line на один запуск и проверьте его в `/proc/cmdline`
- `ld-043` — VM не загружается из-за неверной записи в `fstab`
- `ld-044` — Найдите модуль, обслуживающий виртуальное устройство, и покажите его параметры/зависимости
- `ld-045` — После обновления ядра не хватает нужного модуля в initramfs
- `ld-047` — Система уходит в emergency mode из-за зависшего mount
- `ld-048` — Подготовьте безопасный план обновления ядра с rollback и критериями остановки; проверьте его на двух снимках VM

## Ядерный журнал и системные часы

- `ld-058` — Отделите сообщения ядра от логов приложения при OOM-сценарии
- `ld-062` — Логи двух узлов расходятся по времени
- `ld-191` — После смены времени узлы неверно упорядочивают события и истекают сертификаты

## Диски, разделы, LVM, RAID

- `ld-065` — По `lsblk`, `blkid`, `findmnt` нарисуйте соответствие диск → раздел → FS → mount
- `ld-066` — Добавьте учебный диск, создайте раздел и FS, смонтируйте по UUID
- `ld-067` — Создайте VG/LV на двух учебных дисках и увеличьте LV и FS без потери данных
- `ld-068` — Приложение пишет в корневой FS вместо отдельного тома после сбоя mount
- `ld-069` — Сделайте snapshot LV, измените данные, восстановите копию
- `ld-070` — У VG нет свободных extents, сервис близок к остановке
- `ld-071` — Сравните ошибки и восстановление для RAID1 на виртуальных дисках
- `ld-072` — Разработайте миграцию данных на новый том с контролем целостности, коротким окном переключения и rollback

## Квоты и файловые системы на блочных устройствах

- `ld-074` — Настройте user/group quota в учебном разделе
- `ld-078` — Сравните ext4 и XFS для заданного профиля файлов: создание, удаление, recovery, resize
- `ld-079` — Повреждён учебный FS после аварийного отключения

## Swap и задержки диска

- `ld-087` — Настроенный swap маскирует нехватку RAM и портит latency
- `ld-189` — Дисковые задержки вызывают каскадный timeout приложений

## Профилирование ядра, LSM, аудит ядра

- `ld-157` — Снимите профиль CPU через `perf` или доступный профилировщик и найдите hotspot
- `ld-159` — Используйте eBPF/ftrace в учебной VM для измерения latency одного системного пути
- `ld-163` — Сервис не читает файл при правильных Unix permissions из-за SELinux/AppArmor
- `ld-167` — Создайте аудит изменения одного критичного файла и действий с привилегиями

## Как их вернуть

Нужен хост с настоящей виртуализацией (KVM): отдельный компьютер с Linux или VPS с вложенной виртуализацией. Тогда в рантайм добавляется третий тип среды (`vm`) рядом с `container` и `lxd`; очередь, терминал и независимая проверка по SSH переиспользуются без изменений. На ноутбуке с Windows это возможно только после отключения Hyper-V/WSL2 и включения вложенной виртуализации AMD-V/VT-x в VMware, что ломает Docker Desktop и WSL2.
